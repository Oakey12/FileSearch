# Поиск файлов

Небольшое оконное приложение для Windows, которое ищет файлы по имени в выбранной папке и во всех её подпапках. Написано на Go с использованием графической библиотеки Fyne.

Программа не изменяет и не удаляет файлы: во время поиска она только читает структуру каталогов, а во время предпросмотра — содержимое выбранного файла.

## Быстрый старт

1. Запустите `file-search.exe`.
2. Нажмите **Выбрать папку…** или введите путь вручную. Ручной ввод удобен для сетевых путей и подключённых дисков, например `G:\Документы`.
3. В поле **Имя файла** введите полное имя или только его часть. Например, запрос `отчёт` найдёт `отчёт.xlsx`, `старый_отчёт.pdf` и `ОТЧЁТ-за-июль.docx`.
4. Нажмите **Найти** или клавишу Enter в поле имени.
5. Выберите нужный файл в таблице результатов.
6. Используйте одну из кнопок:
   - **Предпросмотр файла** — посмотреть содержимое, не открывая отдельную программу;
   - **Показать в Проводнике** — открыть папку и выделить найденный файл.
7. Нажмите **Новый поиск**, чтобы очистить путь, запрос и результаты.

## Как работает поиск

После нажатия **Найти** приложение:

1. Убирает пробелы и внешние кавычки из введённого пути.
2. Преобразует путь в абсолютный и проверяет, что такая папка существует.
3. Рекурсивно обходит папку и все вложенные каталоги функцией `filepath.WalkDir`.
4. Сравнивает запрос с именем каждого файла. Сравнение выполняется без учёта регистра и по вхождению строки, а не по точному совпадению.
5. Выводит совпадения таблицей: имя, тип, размер, дата изменения и папка.

Например, запрос `report` совпадёт с `report.txt`, `REPORT-final.pdf` и `my-report-old.docx`.

Поиск выполняется в отдельной горутине, поэтому окно не зависает. Во время обхода
статус анимируется точками, а кнопка **Отмена поиска** позволяет остановить обход
и сохранить уже найденные результаты. На время обхода кнопки запуска поиска и
выбора папки блокируются. Если часть каталогов недоступна из-за прав доступа,
программа пропускает их и показывает количество пропущенных объектов.

> Поиск выполняется только по имени файла. Текст внутри документов программа не анализирует. Маски наподобие `*.pdf` и регулярные выражения не поддерживаются: символы `*` и `?` воспринимаются как обычный текст.

## Как работает предпросмотр

Тип предпросмотра определяется по расширению файла:

| Тип | Поддерживаемые расширения | Что отображается |
| --- | --- | --- |
| Изображения | `.png`, `.jpg`, `.jpeg`, `.gif`, `.bmp` | Изображение, вписанное в окно |
| Текст и код | `.txt`, `.log`, `.md`, `.json`, `.xml`, `.csv`, `.go`, `.js`, `.ts`, `.html`, `.css`, `.sql`, `.yaml`, `.yml`, `.ini`, `.conf` | Текст в режиме только для чтения |
| Word | `.docx` | Извлечённый из документа текст без исходного оформления |
| Excel | `.xlsx`, `.xlsm`, `.xltx`, `.xltm` | Таблица с возможностью переключаться между листами |
| Старые форматы Office | `.doc`, `.xls` | Только сведения о файле |
| Остальные файлы | любые другие | Имя, расширение, размер, дата изменения и полный путь |

Для обычного текста и текста из DOCX читается не более первого 1 МБ. В Excel показываются максимум 500 строк и 50 столбцов каждого листа. Эти ограничения защищают интерфейс от зависания на очень больших файлах. Формулы Excel отображаются как вычисленные значения, если они сохранены в книге; макросы не запускаются. Предпросмотр открывается в отдельном окне и загружается в отдельной горутине.

## Структура проекта

```text
file-search/
├── go.mod
├── go.sum
├── README.md
├── internal/mainFunc/
│   └── explorer_windows.go  # открытие и выделение файла через Windows Shell API
├── internal/varAndConst/
│   └── varAndConstFile.go   # общие константы приложения
└── src/
    ├── main.go              # окно, элементы управления и алгоритм поиска
    ├── preview.go           # предпросмотр файлов
    ├── main_test.go         # тесты поиска
    └── preview_test.go      # тесты предпросмотра DOCX и табличных функций
```

Основные части:

- `main()` создаёт окно Fyne, связывает кнопки с действиями и хранит текущее состояние интерфейса.
- `findFiles()` отвечает только за обход каталогов и формирование списка совпадений. Благодаря этому алгоритм можно тестировать отдельно от окна.
- `showPreview()` и `createPreview()` выбирают подходящий способ показа файла.
- `ShowInExplorer()` вызывает Windows Shell API, чтобы открыть Проводник и выделить файл. Если выделение невозможно, приложение открывает родительскую папку.
- Счётчик `searchGeneration` не позволяет результатам старого фонового поиска заменить результаты нового после нажатия **Новый поиск**.

## Сборка из исходников

### Требования

- Windows;
- Go 1.24 или новее (версия указана в `go.mod`);
- C-компилятор для сборки Fyne на Windows, например GCC из MSYS2/MinGW-w64;
- включённый CGO (`CGO_ENABLED=1`, обычно это значение используется по умолчанию при наличии компилятора).

Проверить Go и GCC можно командами:

```powershell
go version
gcc --version
```

Из корня проекта выполните:

```powershell
go mod download
go test ./...
go build -ldflags="-H=windowsgui" -o file-search.exe ./src
```

Флаг `-H=windowsgui` скрывает консольное окно при запуске графического приложения. Без этого флага программа тоже работает, но рядом с интерфейсом может появиться консоль.

Для запуска без создания `.exe`:

```powershell
go run ./src
```

При первом запуске сборки Go скачивает зависимости из `go.mod`, поэтому она может занять больше времени.

## Возможные проблемы

### Папка не открывается

Проверьте, что путь существует и у текущего пользователя есть право чтения. Путь с пробелами можно вводить как с кавычками, так и без них — внешние кавычки приложение удалит самостоятельно.

### Найдены не все файлы

Посмотрите строку состояния. Если там указано количество пропущенных объектов, часть дерева каталогов была недоступна. Также помните, что приложение ищет в именах файлов, но не в именах папок и не в содержимом документов.

### Не собирается Fyne

Если компилятор сообщает об ошибках CGO или OpenGL, проверьте наличие GCC и доступность его исполняемого файла через переменную `PATH`. Затем повторите `go test ./...` и сборку.

### Файл не выделяется в Проводнике

Приложение сначала пытается выделить файл через Windows Shell API. Если Windows не может обработать путь таким способом, используется запасной вариант: открывается содержащая файл папка.
